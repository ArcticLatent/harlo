Documentation

Every feature of Harlo 2.0 and how to use it.

Harlo is a desktop app for coding agents. Its own server runs the agents in the background on your computer; the window shows what they do, asks you before they act, and lets you read every change. This page goes through all of it, part by part.

Getting started

Install

Download the package for your Linux and install it. Harlo needs an x86-64 processor with AVX2, glibc 2.35 or newer, and git.

The setup guide

The first time Harlo starts, a guide takes you through four steps. You can skip any of them and come back later: Settings → General → Setup guide, or start Harlo with harlo --setup.

  1. Server. Harlo starts its own server, which runs the agents. Nothing to choose here; it shows that the server is up.
  2. Providers. Agents need a model. Connect a provider with an API key, sign in to one in the browser, or set up a model that runs on this computer. See Models.
  3. Git. The name and email that go on your commits.
  4. Theme. Light or dark, and the colours.

Your first session

  1. Click + Project in the sidebar and choose the folder of the code you want to work on.
  2. Press Ctrl+N, or the new-session button beside the project.
  3. Type what you want done and press Enter.
  4. The agent starts working. When it wants to run a command, a card asks you: Allow once, Always allow or Deny.
  5. Open Changes in the rail at the right to read what it changed, and commit it when you are happy.

You can close the window at any point. The server keeps the session running, and Harlo shows where it got to when you open it again.

The window

Sidebar
Your projects and their sessions. The menu at its top switches between servers, when you follow more than one. Filter sessions narrows the list as you type.
Tabs
Each session, file and picture you open gets a tab. Ctrl+Tab and Ctrl+Shift+Tab move between them; Ctrl+W closes one.
The conversation
Your prompts and the agent’s turns: text, lists, tables, code coloured by language, the tools it used and what they returned, and pictures.
The message box
Where you write. Under it are the permissions shield, the agent, the model and its effort.
The rails
The rail at the right opens the panels: Context, Todos, Subagents, Changes, Files, Notes, Side questions and the Terminal. The rail at the left hides and shows the sidebar, and has the phone button, the keyboard shortcuts, Stats, Settings and your avatar.

A panel can be maximized to fill the window; Esc puts it back. Ctrl+, opens Settings, which has a search field that finds a setting by its name.

Sessions and projects

Projects

A project is a folder. + Project adds one; its sessions are listed under it. A session can also be started without a project, for a question that isn’t about any code.

Settings → Projects gives each project a name, a colour, an icon (an image you choose), and the model its new sessions start with. Removing a project from Harlo leaves the folder and its files alone; you choose whether its sessions are kept or archived.

What a session’s row tells you

MarkMeaning
WorkingThe agent is in the middle of a run.
Waits for approvalIt wants to do something and needs your yes.
Asks a questionIt asked you something and waits for the answer.
New answerIt finished since you last looked.

Session actions

Session actions in a session’s header has:

Fork
Makes a copy of the session that you can take another way. In the conversation, Fork from here on one of your prompts copies it up to that prompt.
Move to…
Moves the session to another project or worktree.
Export… and Import a session…
Saves a session as a .json file, and brings one back in, on this computer or another.
Archive
Takes the session out of the lists. It stays on the server.
Delete…
Removes it for good, after you confirm.

Finding your way in a long session

Prompts lists everything you asked in the session; click one to jump to it. Jump to the end returns to the newest message. When a conversation grows past what the model can hold, Harlo has the model summarize it and carries on from the summary; the conversation shows where that happened. /compact does it when you ask.

Pictures

Paste a picture into your message with Ctrl+V, or attach one. Pictures you sent and ones the agent made open in a viewer with zoom, fit, turn, and Show in folder. Pictures in the session’s header lists all of a session’s pictures.

Worktrees

A worktree is a second checkout of a project on its own branch, so two agents can work on the same project without touching each other’s files. Settings → Projects → Worktrees makes and removes them, and can run a setup command (such as npm install) in each new one. When you start a session, choose the worktree as its folder; Move to… moves an existing session into one.

Writing messages

You typeWhat happens
EnterSends the message. While the agent is working, it is queued and sent when the run ends.
Shift+EnterA new line.
Ctrl+EnterSteers a working agent: your message reaches it at its next step instead of waiting for the end.
/ at the startLists commands and skills.
@Mentions a file or folder, a subagent, or an MCP resource.
! at the startRuns the rest as a shell command in the session’s folder, with no model. !git status runs git status.
Tab, Shift+TabSwitches to the next or previous agent.
Ctrl+VPastes text, or attaches a picture from the clipboard.
Ctrl+Shift+DStarts or stops dictation.

Queued messages show above the message box, where you can remove one or send it now as a steer. Stop ends a run; what the agent wrote so far is kept.

Built-in commands

/btw question
A side question. The model answers from what the session already knows, uses no tools, and the question stays out of the conversation. Answers are in the Side questions panel until Harlo closes.
/goal objective
Gives the session a goal to keep working toward. After each run a reviewer reads the conversation and decides whether the goal is met; if not, the agent goes another round, up to 50. The goal shows above the message box with Pause, Resume and Dismiss.
/compact
Summarizes the conversation now, to free up room in the model’s context.
/init
Has the agent look through the project and write an AGENTS.md for it, or bring the existing one up to date.
/review [commit, branch or pull request]
Reviews changes. With nothing named, the uncommitted ones.

Your own commands and your skills are in the same list. See Commands and Skills.

The agent, the model and its effort

The chips under the message box choose who answers. Build does the work. Plan reads and plans but changes no files other than its plans. The model menu lists the models you chose in Settings → Models; the effort chip picks how hard a model thinks, where the model has levels. A session keeps its choices.

Dictation

Press Ctrl+Shift+D or the microphone and speak; press again to stop, and the words are put into the message. Speech is recognised on your computer. Settings → Voice downloads a speech model (the larger one is more accurate and slower) and sets the language and the microphone.

Approvals and permissions

An agent asks before it acts. The card names the action and shows the command or the edit:

AnswerKeyWhat it does
Allow onceAlt+ALets this one action run.
Always allowLets this kind of action run from now on, in every session of the project. The card says exactly what it will cover.
DenyAlt+DRefuses it.
Deny with a reason…Refuses it and tells the agent what to do instead.

What you always allowed is listed in Settings → Agents → Saved approvals. Remove one there to be asked again.

Permission modes

The shield under the message box sets how much a session may do without asking:

ModeMeaning
Agent’s own rulesThe agent decides. Commands usually ask. This is the default.
Ask before edits and commandsEvery edit and every command waits for you.
Don’t askEdits and commands run without asking. A command that wants to leave the sandbox still asks.

Questions

An agent can ask you a question with choices to pick from. Pick one, or choose Something else… and answer in your own words. The run waits and then carries on with your answer.

The sandbox

The commands an agent runs are confined by the Linux kernel (Landlock):

  • A command can read and run what is on the computer, except the places that hold secrets: your SSH keys, sign-ins, browser profiles and Harlo’s own files.
  • It can change the project, the temporary folders and tool caches, and nothing else.
  • The network is not confined.

A command that needs more asks to run outside the sandbox, and that always waits for you unless a rule names it. Settings → Agents → Sandbox turns confinement off; the config file can add folders commands may change and places they can’t read.

A project’s own settings wait for you

A project can bring its own harlo.jsonc. What in it would act for you waits until you allow it: rules that let actions run unasked, MCP servers (programs started on your computer), and commands that run shell lines. A project’s file can never say where requests to a model go or with which key.

Changes, Git and undo

The Changes panel

Open Changes in the rail at the right. It lists files in three groups:

  • This turn: what the agent changed in its last turn.
  • This session: everything the session changed.
  • Uncommitted: everything in the folder that Git sees as changed.

Select a file to see its diff. Only the lines that changed are shown, coloured by language.

Commenting on lines

Click a line of a diff to comment on it. Add as many comments as you like, then press Send to the agent: they go as one message, after whatever is in the message box. Discard drops the comments instead.

Committing and pushing

Write a commit message at the foot of the panel, or press ✦ to have a model write it from the diffs, then Commit. Push sends your commits to the branch’s upstream. Committing needs the folder to be a Git repository on this computer.

Settings → Git holds your name and email, signs in to GitHub (through gh), GitLab (through glab) or a Forgejo server (with an access token) for pushing over HTTPS, and picks the model that writes commit messages. A small, fast model is enough.

Undoing a turn

Undo on one of your prompts takes the session back to before it:

  1. Harlo puts the files the agent changed since then back as they were, and shows what it restored. If you edited one of those files yourself, it warns you first.
  2. Undo again makes it final: the prompt and every later message are removed.
  3. Cancel undo instead brings the agent’s edits back.

Restoring files needs snapshots, which are on unless Settings → Git → Keep snapshots is off.

Panels

Files
The session’s folder as a tree. Click a file to open it in an editor tab; Ctrl+S saves. If the file changes on disk while you have unsaved edits, Harlo asks which version to keep.
Context
How full the model’s context is, the tokens the session used (input, output, reasoning, cache) and what they cost, and which instruction files (AGENTS.md) apply to the session.
Todos
The agent’s working list for a task with several steps: each step, and whether it is waiting, under way or done. The current step also shows above the message box. It is off until you turn on Todo list in Settings → Experimental.
Notes
Your own notes for the project: ideas, decisions, things to remember. A line that starts with - [ ] is a todo; Ctrl+Enter ticks the one under the cursor. Insert into message puts the note into the message box.
Terminal
Shells in the session’s folder, in tabs under the conversation. Ctrl+Shift+C copies, Ctrl+Shift+V pastes.
Side questions
The answers to your /btw questions.
Subagents
The helpers the session started, what each is doing, and a way into each one’s own conversation.
Stats
Your use across sessions for the last 7 days, the last 30 days or all time: the models you used, their tokens and cost, and the model steps of each day.

Commands an agent started in the background are listed above the message box while they run, each with Stop. A long command that is still running can be sent to the background from its row, so the agent can carry on; its result comes back to the session when it ends.

Models

Providers

Settings → Providers lists the providers Harlo knows, the popular ones first. Press Connect on one and choose how to sign in:

  • An API key. Paste it; Harlo checks it as you add it. Get a key ↗ opens the provider’s page for making one.
  • In the browser. OpenAI with your ChatGPT plan, and OpenRouter, sign in on their own pages.
  • An environment variable set where the server runs.

Harlo works with Anthropic, OpenAI, OpenRouter, OpenCode Go, Vercel’s AI Gateway, Cohere and others, and with any server that speaks the OpenAI API. Sign-ins are kept on the server, so every session and the phone use them.

A Claude subscription

A Claude Pro or Max plan works through Claude Code. In Settings → Providers → Claude subscription, install Claude Code if it isn’t there, sign in, and connect. The page then shows how much of the plan’s limits you have used and when they reset.

Which models you see

Providers list many models. Settings → Models chooses which of them the model menus offer; until you choose, the ones you used recently show. The model new sessions start with is set in Settings → General, and a project can have its own in Settings → Projects. A model picked under the message box wins over both.

Models on your own computer

Settings → Local models sets up a model that runs on this computer, with no account and nothing sent anywhere:

  1. Choose the program that runs models: Ollama, which gets models by name, or llama.cpp, which runs one model file and is the quickest. Press Install.
  2. The page reads your graphics card and memory and lists the models that fit, the most capable first. Download one.
  3. Press Serve (llama.cpp) or Start the server (Ollama).
  4. Add to the model menu, and pick the model under the message box.

Models Harlo started run only while Harlo is open.

Agents and what they can do

Tools

An agent canHow
Read and searchReads files, lists what a source file declares (its functions and types with their lines, so it reads only the part it needs), finds files by name and searches their text.
EditWrites new files and edits existing ones. Each change is shown as a diff in the conversation.
Run commandsRuns shell commands in the sandbox, in the foreground or as background jobs that report back when they end.
Use the webReads a page by its address and searches the web.
Start subagentsHands part of a task to a helper in a session of its own. The helper works in the background and reports back.
Ask youAsks a question with choices when it needs a decision.
RememberKeeps a decision as a note for later sessions, and searches earlier sessions.
Use skills and MCP toolsLoads a skill when a task calls for it, and calls the tools of your MCP servers and plugins.
Write scriptsWrites a short script that calls several tools in one step, instead of one call at a time.

The built-in agents

Build and Plan are the agents you talk to. General and Explore are subagents that Build starts for part of a task; Explore only reads. Settings → Agents lists them all.

Your own agents

An agent is a Markdown file in ~/.config/harlo/agents/, or in a project’s .harlo/agents/. The file’s name is the agent’s id, the front matter its settings, and the body its instructions:

---
name: Reviewer
description: Reads changes and points out problems
mode: primary        # primary, subagent, or all
model: anthropic/claude-sonnet-5-5
color: "#4f9dff"
permissions:
  - { action: edit, resource: "*", effect: deny }
---
You review code. Read the changes, say what is wrong and why,
and change nothing yourself.

A file named after a built-in agent changes that agent instead of adding one.

Commands

A command is a prompt you reuse. Put a Markdown file in ~/.config/harlo/commands/ or a project’s .harlo/commands/, and /name sends it. $ARGUMENTS in the text is replaced by what you type after the name. The front matter can set a description, an agent and a model.

---
description: Explain a file to a newcomer
---
Explain $ARGUMENTS to someone new to this codebase:
what it is for, how it is used, and what to read next.

Skills

A skill is a folder with a SKILL.md: instructions the agent loads when a task calls for them. Harlo finds skills in .claude/skills/, .agents/skills/ and .harlo/skills/, in the project and in your home folder, and in ~/.config/harlo/skills/. Type / to attach one to a message yourself. disable-model-invocation: true in a skill’s front matter keeps the agent from loading it on its own. Settings → Extensions → Skills lists the ones found.

Instructions (AGENTS.md)

What you want every session to know goes in AGENTS.md files, which the model reads at the start:

  1. ~/.config/harlo/AGENTS.md (or, without one, ~/.claude/CLAUDE.md), for all your projects.
  2. Each AGENTS.md from the session’s folder up to the project’s root. A folder without one uses its CLAUDE.md.
  3. The files the config’s instructions list names.

A line such as @docs/style.md in one of these files brings that file in too. The Context panel shows which files apply to a session. /init writes a first AGENTS.md for a project.

Notes the agent keeps

The agent keeps the decisions you make as notes, each with the session it came from. A project’s notes reach every session of that project; your own reach all your sessions. Settings → Memory lists them, lets you edit or forget one, and turns the whole thing on or off.

Web search

The first time an agent wants to search the web, Harlo asks whether to allow it. Settings → Tools chooses the search service: Exa, Firecrawl, Parallel, Tavily or TinyFish. Each works without a key within its free limits, and a key of yours lifts them. With a Claude subscription connected, searches can go through it instead.

MCP servers, skills and plugins

MCP servers

An MCP server gives agents more tools: a database, an issue tracker, a browser. Settings → Extensions → MCP servers → Add an MCP server has a list of ready ones, and Your own for any other:

  • A program on the server’s computer: give its command, such as npx -y some-mcp-server.
  • A service at an address. If it asks you to sign in, press Sign in and finish in the browser.

On a server’s page you can connect and disconnect it, turn it off, and remove it. Agents use its tools chooses between Through scripts (the agent calls the tools from a script it writes) and Listed one by one. MCP servers are saved in harlo.json and work for every session on the server. In a message, @ mentions a server’s resources.

Plugins

A plugin is a git repository that brings skills, commands, agents, MCP servers and tools of its own. In Settings → Extensions → Plugins, type the repository’s address and press Add, or press Browse to see the ones people have published.

  • Harlo fetches a plugin only when you add or update it, never on its own.
  • What would act for you waits for your yes: the programs it starts, the code it runs, and what that code may reach. An update that asks for something new waits again.
  • Your own skills, commands, agents and MCP servers win over a plugin’s of the same name.
  • Nobody reviews the published list. Read a plugin before you add it.

To write one, see the plugin guide, which has a starter to copy.

Schedules

A schedule has the server do something at a time, even with Harlo closed. Open Settings → Schedules and press New schedule:

  1. Name it.
  2. When: once at a time, every so often, or on a repeating schedule.
  3. What it does: sends a prompt, to a new session named after the schedule or to a session you choose; or runs a shell command or a script with no model.

A schedule’s page shows its next run and how its earlier runs went, and has Pause, Resume and Delete. A run that came due while the server was down runs once when the server is back; the other repeats it missed are skipped. Allow schedules turns them all off.

The server and other computers

Harlo’s server

The agents run in harlo-server, a background service on your computer. Harlo starts it when none is running and leaves it running when the window closes, so sessions, schedules and the phone keep going. With Settings → General → Keep running in the tray, closing the window leaves Harlo in the tray too, still telling you when a session needs you; Ctrl+Q quits it.

Other computers

Harlo can follow a Harlo server on another computer over SSH: a GPU box, a build server, a NAS. Install Harlo there, then in Settings → Server → Other computers type me@host, or a name from your ~/.ssh/config, and press Add and follow. Harlo runs your system’s ssh, so your keys, agent and jump hosts work as they do in a terminal, and it starts the server there if none is running. The menu at the top of the sidebar switches between computers. Sessions on the other computer run there, with its files, its models and its sign-ins.

The iPhone app

Pairing

  1. On the computer, click the phone button in the rail at the left, or open Settings → Phone, and turn on Phone access.
  2. Press Show a code. The QR code works once, for ten minutes.
  3. Scan it with the Harlo app. A pairing link to paste is there too.

On the same Wi-Fi the phone connects directly. Turn on Reach Harlo from anywhere to use it away from home: messages then pass through Harlo’s relay, end-to-end encrypted, so the relay can’t read them.

What you can do from the phone

  • Follow sessions live, send messages, start new sessions, and stop a run.
  • Answer questions and approvals, in the app or straight from a notification.
  • Read changes, diffs, files and branches; undo a turn; edit and resend a message.
  • Manage the queue, permission modes and pinned sessions; change the model.
  • Watch a run in a Live Activity on the Lock Screen, and see your sessions in a home-screen widget.

The app takes your desktop’s theme and avatar. The phone button in the rail pauses and resumes notifications to the phone. Settings → Phone lists paired phones, removes one, and sends a test notification. More help is on the support page.

Your own relay

The relay stores nothing and can’t read what it passes on. If you would still rather run your own, harlo-relay is in the source; the README says how. Set HARLO_RELAY=https://… where Harlo and its server start.

Experimental features

Settings → Experimental has a switch for each feature that is still being tried. A change applies to every session on the server, and to the phone.

SwitchAt firstWhat it does
Todo listOffAgents keep a list of a task’s steps, which you watch in the Todos panel and above the message box. Each update of the list is an extra step: on a task of three changes it used about half more tokens.
File outlinesOnAgents list what a source file declares, its functions and types with their lines, and read only the part they need.
Session tools in scriptsOffThe scripts agents write can also read, search, edit and run commands, each under its own rules. On small jobs this cost more tokens.
Cached instructionsOffFor OpenAI’s GPT-6.2 and later: sends the instructions at the start of the conversation, where the provider’s cache keeps them.

When Harlo follows a server on another computer, these are set in that computer’s config file.

Updates

Harlo looks for a new version when it opens and every six hours, and offers it in a notice. It updates with your system’s package manager, which may ask for your password, or replaces the AppImage, then offers to restart. Settings → General → Updates has Check now and turns the checking off. A Harlo you built from source doesn’t update itself.

Notifications in your own words

Each notification’s title and message can be rewritten in Settings → Notifications → Templates. Names in braces are filled in when it is sent; the page lists the ones you can use. Leave a field empty for the default.

The config file

Settings covers most things. Underneath, the server reads ~/.config/harlo/harlo.jsonc (or harlo.json). A project can add its own harlo.jsonc, or one in its .harlo/ folder, and the nearer file wins. Changes apply as soon as the file is saved. Comments are allowed.

{
  // The model new sessions start with: "provider/model".
  "model": "anthropic/claude-sonnet-5-5",

  // A server of your own that speaks the OpenAI API.
  "providers": {
    "lab": {
      "name": "My lab",
      "settings": { "baseURL": "http://192.168.1.20:8080/v1", "apiKey": "…" },
      "models": {
        "coder": { "name": "Coder", "limit": { "context": 128000, "output": 8192 } }
      }
    }
  },

  // The last rule that matches decides: allow, ask or deny.
  "permissions": [
    { "action": "shell", "resource": "git status *", "effect": "allow" },
    { "action": "edit", "resource": "*.lock", "effect": "deny" }
  ],

  "mcp": {
    "servers": {
      "docs": { "type": "remote", "url": "https://example.com/mcp" },
      "tools": { "type": "local", "command": ["npx", "-y", "some-mcp-server"] }
    }
  },

  // More folders commands may change, and more places they can't read.
  "sandbox": { "writable": ["~/notes"], "hidden": ["/srv/keys"] }
}
KeyWhat it sets
modelThe model new sessions use, as "provider/model", with #variant for an effort level.
small_modelA cheaper model for small jobs, such as naming a session.
providersProviders with an OpenAI-compatible API: a name, settings.baseURL, settings.apiKey, and their models. A project’s file can’t set these.
permissionsRules: an action (read, edit, shell, webfetch, websearch, … or *), a resource pattern (a path or a command; * matches anything) and an effect.
instructionsMore instruction files: paths and * patterns.
skillsMore folders to look for skills in.
commands, agentsCommands and agents written in the file instead of as Markdown files.
mcp.serversMCP servers by name: "type": "local" with a command, or "type": "remote" with a url and optional headers. "codemode": false lists a server’s tools one by one.
websearch{ "provider": "exa" } names the search service; false turns web search off.
sandboxfalse lets commands run unconfined. writable and hidden add folders.
snapshotsfalse stops recording the files for undo.
automationsfalse turns schedules off.
compactionlimit: the context size, in tokens, at which a session is summarized.
experimentalThe switches of Settings → Experimental: todo, outline, scriptTools and cachedInstructions, each true or false.

How a shell rule is read

A command line is decided part by part: each command around ;, && and |, and each file it writes with >. The strictest answer stands, so a rule that allows git status * never covers what a line runs after it. A file outside the project is also decided as external_directory.
